## 3. Architecture now implemented

```text
React/Vite portal
  -> same-origin Nginx /api and /ws proxy (or Vite dev proxy)
  -> Fiber authentication + active-user check + permission middleware
  -> role/ownership-scoped handlers
  -> full plan gate -> content/registry-bound ValidationToken
  -> dispatch-time resolved-parameter revalidation
  -> registered tool -> remote MCP or opt-in demo.echo mock
  -> synchronous rollback-aware store mutation
  -> memory mode OR AES-256-GCM encrypted PostgreSQL snapshot
```

The tool/rule registries intentionally remain JSON source-of-truth files. A
runtime registry mutation persists the JSON, atomically swaps the in-memory
snapshot, and changes the registry hash so an old validation token fails.
Compose mounts those registries on the durable `registry_data` volume.

## 7. Honest remaining boundaries and external actions

These do not invalidate the requested core completion, but they must not be
hidden behind a generic "production-ready" claim.

1. **Revoke, rotate, and scrub the historical Gemini credential.** This is the repository owner's immediate action.
2. **Start Docker Desktop before Compose acceptance.** Compose parses correctly, but the local engine was unavailable for an image build/start in the final pass.
3. **Keep one backend writer per state key.** PostgreSQL intentionally refuses a second writer; the whole-state snapshot is not a horizontal-write architecture.
4. **Plan normalized SQL repositories for scale.** Every mutation serializes/encrypts the complete state while holding the write lock; very high write rates, large uploads, partial SQL queries, and horizontal writers require a later migration.
5. **Back up registry JSON separately.** Compose supplies `registry_data`; non-Compose deployments must mount durable registry paths.
6. **Redis is not authoritative.** It is still an in-memory policy-cache placeholder; distributed caching/pub-sub is future work.
7. **External services remain external.** Real MCP needs its middleware; the research semantic path needs the embedding service; live provider tests need valid credentials/network access.
8. **Token cost is intentionally zero without pricing.** Counts are provider-measured where available, but no authoritative price table is implemented.
9. **Application API keys are management records only.** They are not currently an alternative request-authentication mechanism.
10. **Optional identity features intentionally return `501`.** Password recovery/reset, email verification, 2FA, OAuth, and invitations require providers/product decisions outside the master prompt.
11. **Execution cancel is unavailable for synchronous runs.** Cancellation requires an asynchronous job model.
12. **Canvas-only node/edge conversion is limited.** The normal builder/demo supplies YAML; converting an arbitrary canvas without YAML is not implemented.
13. **Frontend code splitting is desirable.** The current bundle passes but retains the 683.49 kB chunk warning.
14. **Go race mode was unavailable.** The environment has CGO disabled; normal tests, vet, concurrency tests, and real PostgreSQL tests passed.
15. **Production egress should be constrained.** Admin-configured provider/webhook/integration probes accept HTTP(S) destinations; redirects and URL credentials are refused, but deployment network policy should still restrict sensitive internal destinations.
16. **Rate limiting is process-local.** A distributed limiter is needed if the snapshot architecture is later replaced with multiple backend replicas.
