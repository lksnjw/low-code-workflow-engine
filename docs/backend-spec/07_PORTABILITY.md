# Go-specific constructs and port assessment

The target assumed by this assessment is a language with structural typing and runtime type erasure, such as TypeScript/JavaScript. “Equivalent” below means equivalent observable behavior; “same guarantee” means the property is enforced at the same boundary and strength, not merely recreated by convention.

## 7.1 Constructs that do not translate directly

### Package-private dispatch capability

**Go mechanism.** `DispatchCapability` is exported so it can cross package boundaries, but all its fields and the nested `dispatchProof` type/field are unexported. Only validator-package code can populate a usable value. `Tool.Execute` requires that concrete type, and MCP also performs runtime usability/action/parameter-hash checks. [backend/internal/core/validator/dispatch_capability.go:13-85](../../backend/internal/core/validator/dispatch_capability.go) [backend/internal/tools/tool_interface.go:9-13](../../backend/internal/tools/tool_interface.go)

**Property.** Ordinary external Go source cannot construct or mutate the proof-bound fields; the compiler rejects the witness literal. Runtime checks additionally prevent the zero value and content mutation from dispatching. [backend/internal/tools/dispatch_capability_compile_fail.go:1-12](../../backend/internal/tools/dispatch_capability_compile_fail.go) [backend/internal/tools/mcp_client.go:62-76](../../backend/internal/tools/mcp_client.go)

**Nearest erased/structural equivalent.** A TypeScript `private`/branded field is erased and can be forged with assertion or raw JavaScript, so it weakens the compile-time/package guarantee. A closure-owned `WeakSet` of minted frozen objects, an unexported module `Symbol`, or an HMAC-authenticated opaque byte token can preserve a runtime minting boundary, but not Go's “outside source cannot name/populate the field” compile-time fact. To maintain security strength, the port must treat this as a runtime cryptographic/identity capability and keep the tool transport function inaccessible except through the verifier; type branding alone is insufficient.

### Build tags and binary absence

**Go mechanism.** `//go:build experiment` and `!experiment` select mutually exclusive source files at compilation. Baseline setter/state/audit and experiment-safe interface are literally absent from a default package; `cmd/run-experiment` has no default-build source. The `ignore` witness is absent from every ordinary build. [backend/internal/core/runner/executor_type_experiment.go:1-24](../../backend/internal/core/runner/executor_type_experiment.go) [backend/internal/core/runner/executor_type_production.go:1-22](../../backend/internal/core/runner/executor_type_production.go) [backend/cmd/run-experiment/main.go:1-12](../../backend/cmd/run-experiment/main.go) [backend/internal/tools/dispatch_capability_compile_fail.go:1-12](../../backend/internal/tools/dispatch_capability_compile_fail.go)

**Property.** Production cannot call a bypass symbol because it is not compiled into the package/binary; this is stronger than a runtime flag defaulting off.

**Nearest equivalent.** Use separate production/experiment entry graphs and packages, with the production bundler forbidden from resolving the experiment module; then scan the final artifact for forbidden exports/strings and exercise it. Environment-condition branches or tree-shaking hints weaken the guarantee because bypass source remains in the compilation universe and optimizer behavior becomes trusted.

### Strict YAML decoding

**Go mechanism.** `yaml.v3.Decoder.KnownFields(true)` maps directly into a statically declared `WorkflowBlueprint`, followed by a second decode that must return EOF. Go validation tags then enforce required fields. [backend/internal/core/validator/registry_validator.go:1029-1045](../../backend/internal/core/validator/registry_validator.go) [backend/internal/models/workflow.go:19-48](../../backend/internal/models/workflow.go)

**Property.** Unknown mapping keys, incompatible field types, syntax errors, and multiple documents are rejected before gate evaluation.

**Nearest equivalent.** Parse exactly one YAML document into unknown data, then validate it with a runtime schema configured to reject additional properties recursively and preserve numeric/null distinctions. This can preserve the behavior if the schema is generated/maintained as the sole contract and has tests for every nested field. A TypeScript interface alone provides no runtime rejection and weakens the property.

### Interface satisfaction and import-boundary evidence

**Go mechanism.** Interfaces are satisfied implicitly by method sets; `ExperimentSafeTool` embeds `Tool` and adds a marker method, then runtime type assertions reject every implementation/fallback without that method. Separately, boundary tests invoke `go list -deps` and compare canonical package import paths, proving that validator has no transitive synthesizer/model-provider/context/company dependency. [backend/internal/tools/experiment_safety.go:7-30](../../backend/internal/tools/experiment_safety.go) [backend/internal/core/context/import_boundary_test.go:16-69](../../backend/internal/core/context/import_boundary_test.go) [backend/internal/core/company/import_boundary_test.go:10-25](../../backend/internal/core/company/import_boundary_test.go)

**Property.** The compiler verifies method signatures at each use, the experiment gate checks marker satisfaction at runtime, and the Go toolchain exposes the actual compiled transitive import graph.

**Nearest equivalent.** Structural TypeScript interfaces reproduce development-time shape checking but disappear at runtime; use an unforgeable runtime registration/brand for experiment safety. Recreate import-boundary evidence with dependency-cruiser/bundler metafiles or AST resolution against the exact production graph, and fail CI on forbidden transitive modules. This preserves the architecture claim only if dynamic imports, path aliases, native extensions, and runtime service locators are included.

### Store mutexes, goroutines, and synchronous hooks

**Go mechanism.** `StoreMutex` wraps `sync.RWMutex`; every write `Unlock` executes persistence while the exclusive lock is still held. Read locks can coexist. Atomic counter/failure generation are lock-free. PostgreSQL adds its own mutex and advisory single-writer lock. The runner launches no goroutine; request execution and persistence are synchronous. [backend/internal/repository/persistent_store.go:23-50](../../backend/internal/repository/persistent_store.go) [backend/internal/repository/memory.go:28-34](../../backend/internal/repository/memory.go) [backend/internal/storage/postgres.go:28-34](../../backend/internal/storage/postgres.go) [backend/internal/core/runner/executor.go:49-170](../../backend/internal/core/runner/executor.go)

**Property.** A serialized snapshot cannot observe an in-progress map mutation protected by the store write lock; multiple goroutines cannot concurrently read/write native maps; a single PostgreSQL writer owns the aggregate.

**Nearest equivalent.** A single JavaScript event loop prevents simultaneous instructions but not interleaving across `await`; mutations must execute in an explicit async critical section/transaction whose lock remains held through serialization/save/rollback. Worker-thread or multi-process deployments need a real mutex/message owner plus the database advisory lock. An ordinary object plus async save weakens snapshot consistency.

### Typed nil and interfaces

**Go mechanism.** An interface value is nil only when both dynamic type and value are nil. Constructors that accept concrete pointers (`*RegistryValidator`) reliably reject nil pointers, but checks on interfaces such as `StateStore`, `Codec`, `analysisprovider.Provider`, `Tool`, and provider implementations can see a typed-nil pointer as nonnil and dispatch a method that may panic. [backend/internal/core/runner/executor.go:38-47](../../backend/internal/core/runner/executor.go) [backend/internal/repository/persistent_store.go:55-61](../../backend/internal/repository/persistent_store.go) [backend/internal/core/analysisprovider/provider.go:14-17](../../backend/internal/core/analysisprovider/provider.go) [backend/internal/tools/registry.go:8-18](../../backend/internal/tools/registry.go)

**Port consequence.** JavaScript has one `null`/`undefined` concept rather than a typed-nil interface pair, so exact bugs/edge behavior should not be imitated. Normalize dependencies at construction and reject nullish or invalid branded implementations. This strengthens rather than weakens the intended contract, but it is not bit-for-bit failure equivalence.

### Zero values with domain meaning

Go zero values are actively semantic here: blank step kind means tool; empty tool status is executable; empty allowed roles permit everyone; zero analysis limits select defaults; zero retry means no retry and only preliminary warning for selected write actions; nil persistence backend means memory mode; nil slices/maps encode differently from empty values; an all-zero capability is unusable; empty permissions can mean an intentional revocation and are preserved across persistence normalization. [backend/internal/models/workflow.go:33-56](../../backend/internal/models/workflow.go) [backend/internal/core/validator/registry_validator.go:205-231](../../backend/internal/core/validator/registry_validator.go) [backend/internal/core/runner/analysis.go:58-67](../../backend/internal/core/runner/analysis.go) [backend/internal/storage/storage.go:19-29](../../backend/internal/storage/storage.go) [backend/internal/core/validator/dispatch_capability.go:19-37](../../backend/internal/core/validator/dispatch_capability.go) [backend/internal/repository/persistent_store.go:406-433](../../backend/internal/repository/persistent_store.go)

An erased-language port must use explicit defaults and distinguish absent, null, empty, false, and zero in its runtime schemas. Applying JavaScript truthiness or generic defaulting (`x || default`) would change these contracts. This behavior is preservable, but only with field-by-field conformance tests.

## 7.4 Honest recommendation

The HTTP surface, DTO/runtime schemas, bcrypt/JWT logic, company/relevance/redaction utilities, semantic retrieval, provider clients, structured-output subset, registry file codec, AES-GCM/PostgreSQL adapter, logging, and preliminary parser can be ported without weakening a proven property if their golden wire/error/hash fixtures pass. They are not the source of G1's compile-time boundary. [backend/internal/api/routes/routes.go:12-215](../../backend/internal/api/routes/routes.go) [backend/internal/storage/codec.go:15-98](../../backend/internal/storage/codec.go)

Do **not** directly port the full validator plus tool dispatch into an erased structural type system and claim equivalent G1. TypeScript `private` fields, brands, and interfaces do not preserve the package-private capability guarantee, and a runtime feature flag does not preserve production-binary absence. Either keep the Go validator/tool boundary as an isolated service/library authority, or redesign it around cryptographically authenticated single-use/short-lived capabilities, a non-exported transport endpoint, separate production/research artifacts, and new adversarial proofs. [backend/internal/core/validator/dispatch_capability.go:13-85](../../backend/internal/core/validator/dispatch_capability.go) [backend/internal/core/runner/executor_type_experiment.go:1-67](../../backend/internal/core/runner/executor_type_experiment.go)

The runner, repository, registry mutation/context/import pipeline, and handlers around them require redesign rather than translation because correctness depends on synchronous lock scope, atomic snapshot publication/rollback, and pre-dispatch ordering. A naive async port will introduce interleavings not present in the Go implementation. [backend/internal/repository/persistent_store.go:23-102](../../backend/internal/repository/persistent_store.go) [backend/internal/core/runner/executor.go:118-166](../../backend/internal/core/runner/executor.go) [backend/internal/core/registry/manager.go:137-260](../../backend/internal/core/registry/manager.go)

Finally, the empirical recall/precision results belong to the frozen Go evaluator and artifacts. They are not inherited by a port. A new implementation must replay all 120 cases, compare per-case verdict/error/rule evidence, reproduce dispatch-spy tests, prove import/bundle exclusions, and publish separate results under its own artifact hashes before making the same claims.
