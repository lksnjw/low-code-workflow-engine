## Actual layering and violations

The effective assembly direction is `cmd/server -> routes -> handlers -> core/repository/tools`; `repository -> storage`, while leaf DTOs and small ports (`models`, `analysisprovider`, `structuredoutput`, `authn`, `redact`) sit below those layers. [backend/cmd/server/main.go:11-28](../../backend/cmd/server/main.go) [backend/internal/api/routes/routes.go:3-10](../../backend/internal/api/routes/routes.go) [backend/internal/repository/persistent_store.go:3-24](../../backend/internal/repository/persistent_store.go)

This is not a strict ports-and-adapters/onion dependency rule. Three concrete inward-dependency violations are present: `core/runner` imports the concrete `internal/tools` adapter/registry; `core/validator` imports the concrete repository aggregate to audit; and `config` imports `core/registry` to validate/load registry material. ## Entry points

### `cmd/server`

Construction order is: load config; construct logger; validate config; optionally probe MCP identity; prepare runtime registries; initialize the Redis placeholder; construct storage codec/backend and repository; reconcile orphaned executions; bootstrap the administrator; apply development role and environment-backed settings; construct synthesizer and schema validator; load the registry bundle; construct registry validator, search, and chat orchestration; construct MCP client and executable-tool registry; construct executor, healer, and HTTP handler; backfill domains; generate registry context and install the tool-upsert callback; optionally load sample seed preview; construct Fiber with CORS/request logging/persistence guard; register routes; listen. [backend/cmd/server/main.go:31-235](../../backend/cmd/server/main.go)

It terminates on logger construction failure, invalid config, a production connection to identified mock ERP, registry initialization, encryption/storage initialization or restore, administrator bootstrap, registry bundle loading, invalid MCP mode, domain backfill, context generation, sample preview loading, or listener return; inability to identify the MCP backend is logged and tolerated. ### `cmd/generate-eval-dataset`

It parses tool-registry, rule-registry, and output flags, calls `eval.Generate`, exits fatally on its error, and otherwise prints `eval.FormatSummary`; the default build includes this command. [backend/cmd/generate-eval-dataset/main.go:11-21](../../backend/cmd/generate-eval-dataset/main.go)

### `cmd/mock-erp`

It loads config, refuses `APP_ENV=production`, loads the runtime tool JSON and mock fixture configuration, constructs the mock service, sorts/logs tool names, and listens only on `127.0.0.1`; it exits fatally on production mode, registry/config/service errors, or server return. [backend/cmd/mock-erp/main.go:18-42](../../backend/cmd/mock-erp/main.go)

### `cmd/run-experiment`

This command exists only in `experiment` builds. It parses dataset/registry/output flags, requires the exact environment value `experiment`, loads cases, runs `eval.RunExperiment`, prints metrics/artifact paths, and exits status 1 on any checked error.
