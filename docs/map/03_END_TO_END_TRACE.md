# End-to-End Trace

## Scope and persistence model

This trace follows the reachable chat-to-canvas-to-run path. The chat request and the later run are two separate HTTP interactions: chat returns a validated YAML artifact, while the browser explicitly transfers that artifact to the canvas before the canvas creates, publishes, and runs a stored workflow (`frontend/src/components/chat/ChatArtifactPanel.jsx:290-300`, `frontend/src/components/canvas/WorkflowBuilderCanvas.jsx:395-425`).

“Persisted” below means written to the repository store. With `STORAGE_DRIVER=postgres`, every write-lock release synchronously encrypts and saves a snapshot; with no state backend the same maps are memory-only and are lost on process exit (`backend/cmd/server/main.go:74-100`, `backend/internal/repository/persistent_store.go:23-40`, `backend/internal/repository/persistent_store.go:52-102`). A failed durable save rolls the mutation back and the mutating HTTP request becomes a retriable 503 (`backend/internal/repository/persistent_store.go:78-95`, `backend/internal/api/middlewares/persistence.go:13-52`).
