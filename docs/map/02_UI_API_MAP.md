# UI to API wiring map

The browser uses a real Axios client whose base URL is `VITE_API_BASE_URL` or `/api`; no production page swaps that client for a local data provider. (`frontend/src/config/axios.js:1-10`, `frontend/src/config/app.js:5-10`)

Every protected screen also causes the application shell to call `GET /health` and `GET /notifications`; those calls are omitted from individual rows below to keep page-specific wiring visible. (`frontend/src/components/navigation/Topbar.jsx:97-105`, `backend/internal/api/routes/routes.go:17-17`, `backend/internal/api/routes/routes.go:206-209`)

In the status notes, `L`, `E`, and `Ø` mean explicit loading, error, and empty states respectively. The route definitions and permission surfaces are centralized in `protectedRouteDefinitions`. (`frontend/src/config/router.jsx:52-89`, `frontend/src/config/router.jsx:95-123`)
