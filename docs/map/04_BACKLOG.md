# Two-Week Work Backlog

## How to use this list

The ranking puts security and permission correctness first, then durability and core workflow fidelity, then product completeness and cleanup. Effort is **S** (under 2 hours), **M** (under one day), or **L** (over one day), as requested. Each “Start here” note names the first file/function to open and is grounded in the cited implementation.

## Suggested two-week cut line

For a two-week implementation window, complete items 1–5 and all **[QUICK WIN]** items first, then choose either the canvas track (items 6, 18, 24, 26) or the asynchronous execution track (items 7 and 27); attempting both large tracks in one short window would span the independent canvas-schema and job-lifecycle dependencies shown above (`frontend/src/utils/workflowCanvas.utils.js:54-157`, `backend/internal/api/handlers/execute_handler.go:63-167`). The remaining L-sized account, integration, intent, and broad UI-surface items should be carried as explicitly scoped follow-on work rather than silently represented as complete (`backend/internal/api/handlers/auth_handler.go:202-224`, `backend/internal/core/orchestrator/chat_orchestrator.go:47-116`, `backend/cmd/mock-erp/handlers.go:14-67`).
